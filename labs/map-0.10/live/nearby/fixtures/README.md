# Synthetic nearby-service fixture — local tests only

Run `bash scripts/test-nearby.sh` from the continuation root. It runs 19 model/source cases plus 14 fixture/controller cases. `server.test.mjs` starts a real HTTP listener bound only to 127.0.0.1 on an ephemeral port; each test closes its listener, sockets and timers. No external API/provider requests are made.

The fixture serves allowlisted map modules, a synthetic configuration, four fake places at coordinates near 0,0 and a valid 16×16 checker PNG. All records/pages/attribution say SYNTHETIC. The served fixture controller substitutes a fixed synthetic geolocation object; Permissions-Policy disables actual geolocation. Opening this fixture manually therefore does not request a real device fix. Only center 0,0 with radius 3000 is accepted. Unknown fields/arbitrary locations are rejected. Nothing is persisted or logged; no account, key or victim location is involved. It is not a real geodata/street-map service. It must never be deployed or configured in a real-user build.

The default production `config.mjs` is unchanged and disabled. The fixture returns its own configuration in HTTP responses without changing that file. Fault modes exercise 503, redirect, oversized body and delay. Foreign Origin/Host, invalid JSON/method, unallowlisted files and invalid tiles are rejected. Headers include no-store, no-referrer, self-only CSP and real geolocation denied.

`controller.test.mjs` runs the ACTUAL map.mjs module in Node VM modules with a minimal DOM/geolocation double and real HTTP calls to the fixture. This is materially more than source-string assertions, but NOT browser rendering, accessibility, WebView or physical Android execution. Covered: automatic categories, permission denial/manual area, late fix after Close, Close during request, pagehide/stale tile error, unavailable states, disabled defaults, invalid manual input and bounded zoom. Images are not actually decoded/rendered by the DOM double; PNG chunk CRC is independently checked.

No adb/emulator binaries were found on PATH or in the available SDK tools, and /dev/kvm is absent. No installation or privileged changes were attempted. The Android shell correctly remains HTTPS-only: this HTTP loopback fixture is for host tests, not a TLS bypass or Android end-to-end claim. Android runtime testing needs an available emulator/device and a separately trusted synthetic HTTPS setup. Do not turn off certificate validation or expand cleartext settings to make this fixture load.
