# 0.9 operation, cost and deployment boundaries

Nothing was deployed. No account, domain, paid resource or real operator grant/key was created. Loopback tests use synthetic positions and private ephemeral test material. The APK endpoint remains blank.

The service now has a real local operator provisioning/initialization path and coordinate-free durable state, not just an in-memory design. It still needs an accountable operator, private distribution/support process, approved TLS origin, private state-key custody and tested infrastructure. Preparation files must not be published or sent as recipient links. The key and valid database are both needed; losing either can prevent recovery.

SQLite transaction/crash behavior is tested with actual process termination. It is one authoritative database/process, not distributed high availability, a power-loss hardware certification or protection from a privileged coherent old-backup restore. The integrity manifest detects tested partial modifications/replay, while an internally consistent old snapshot can still omit later revocations. Restoring stale state with the same identity is unsafe. Explicit generation replacement or separately consistent revocation state is a disaster-recovery policy decision, with continuity costs that must be disclosed.

Prepared reservations prevent one slot's abandoned Until Stop session from occupying another slot's reservation. They do not provide infinite admission or prevent network, CPU, storage or shared-rate-limit denial of service. Adding private grants requires capacity and controlled add-only installation while the state is not live; restart keeps existing links but temporarily loses RAM coordinates. No hidden idle session eviction is used. Private offline disable/rotation/enable and authenticated CAS recovery are implemented; default token maintenance preserves active sessions, with an explicit option to end the current link. This is operator recovery code, not a staffed or automatically trusted support service. Production sizing, filesystem/fsync behavior, checkpoint/backup settings, load, maintenance and incident response need separate validation.

At-rest encryption and coordinate-free durable records do not prove no infrastructure copies. Review OS swap/core dumps, TLS/reverse-proxy request/header/body logging, provider retention, backups, access, certificates/renewal and all telemetry before use. Terminal/idempotency/slot metadata and pseudonymous correlation remain sensitive even without saved coordinates. The operator processes plaintext positions in memory; no end-to-end encryption is claimed.

For a supported pricing example and request-volume arithmetic, see [09_TRADEOFFS.md](09_TRADEOFFS.md). These are illustrative costs, not a provider selection, performance measurement or purchase. Domain, security review, operations/support, traffic and any future geodata can exceed base compute. No total production budget is established.

No ADB/emulator/Android runtime exists here. Native location/permissions, HTTPS adapter, Keystore, selected-file provider, foreground lifecycle, lock/Doze/OEM behavior, system Stop, install/update and accessibility remain unexecuted. Earlier Chromium startup was blocked by socket permissions and the browser could not reach the executor listener. No new visual/browser test is claimed; polish is deferred.

The recipient still has no street-address lookup. A disclosed external Google Maps snapshot is not an embedded or continuously updating map. Private/self-hosted map/address data would require a separate coverage, licensing, size, privacy, retention and cost decision. No unreviewed geocoder or external attestation service was added.
